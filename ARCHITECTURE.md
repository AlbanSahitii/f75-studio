# Architecture

F75 Studio is a Tauri 2 menu-bar app. A Rust core talks HID to the keyboard. Everyday settings live in a native menu (`tray.rs`), and a React + TypeScript key editor opens in a window only on demand. At rest there is no web view and nothing polls: the menu re-reads the keyboard when the pointer reaches the icon.
The editor follows Logitech Options+. The device is the centre of the screen, you click a part of it to change it, and changes apply immediately.

```
┌────────────────────────── UI (src/) ──────────────────────────┐
│ App.tsx        shell: polling, optimistic writes, Undo        │
│ Keyboard.tsx   the F75 render + the light it casts            │
│ panels.tsx     Lighting · Keys (macros) · Performance         │
│ keys.ts        labels, key-press capture (pure, node --test)  │
│ device.ts      typed invoke() wrappers + browser preview      │
└──────────────────────────────┬────────────────────────────────┘
                               │ Tauri commands (JSON)
┌──────────────────── core (src-tauri/src/) ────────────────────┐
│ tray.rs      menu-bar menu (pure model + Tauri glue)          │
│ lib.rs       commands: status, snapshot, set_lighting,        │
│              set_performance, set_key, set_key_colours,       │
│              set_palette_colour, set_macro, restore_original  │
│ device.rs    find the F75, send/receive reports  ← only I/O   │
│ protocol.rs  encode/decode bytes                 ← pure, TDD  │
└──────────────────────────────┬────────────────────────────────┘
                               │ hidapi (IOKit on macOS)
                     AULA F75 over USB-C (258a:010c)
```

## Rules that shape the code

- **Protocol is pure.** `protocol.rs` turns intents into bytes and back. Its tests use bytes captured from a real F75 (`src-tauri/fixtures/`). Synthetic bytes appear only to exercise a rule taken from the decompiled vendor code, and are marked as such. Factory reset isn't representable.
- **One I/O module.** `device.rs` opens the HID handle. Every write is read back and must match.
- **The UI holds no protocol knowledge.** It sends typed values (`Lighting`, `KeyAction`) and receives them decoded. The browser preview's data is generated by the Rust code (`cargo test -- --ignored preview`).
- **Idle costs nothing.** No window, web view or timer at rest. The editor's keyboard is drawn once and never animated. If something animates, it uses only `transform`/`opacity`.
- **State lives on the keyboard.** Every change is a read-modify-write of the current block. The first time the app reads a keyboard, it stores the original blocks in the app-data folder for *Restore original settings*.

## Transports

| Connection | VID:PID | Status |
|---|---|---|
| USB-C cable | `258a:010c` | supported: feature report `0x06`, 520 bytes |
| 2.4 GHz dongle | `3554:fa09` | detected; settings need the cable (different protocol, not implemented) |
| Bluetooth | `3554:fa07` | detected; same as the dongle |

- **Macros belong to keys, and keep their numbers.** Recording a macro onto a key takes a number no other key plays and empties numbers nobody plays, so macro memory doesn't fill up with leftovers and no other key ever changes.

## Next

- **Tap layer:** the board stores it and the editor writes it, but what the firmware does with it is unconfirmed.
- **Knob turning:** key 84 is only the knob's press (`07 00 00 1D`: mute, or the next effect in Lighting mode). Remapping it leaves turning to the knob mode (seen in Volume mode); what turning sends can't be changed yet.
- **Wireless protocol** (report `0x13` on the dongle and Bluetooth), so settings can change without the cable.
- **Per-app profiles** in the menu-bar agent.
